# Closing record layout

Use `docs/goals/<goal-id>/README.md` in this order. The target file holds the detailed agreed report; this record provides its concise outcome and entry points. Retain this layout on later resumption or closure.

```markdown
# Working goal — <title>

Goal ID: `<goal-id>`

Status: <lifecycle status>

Started from: `<immutable start HEAD>`

Outcome: <agreed outcome>

## Result

<What was achieved, key measurements, gate summary, and material limitations.
For unsuccessful closure, state partial results and unmet gates.>

## Reproduction

<Required environment and inputs, brief copy-paste commands, and expected result.
If nothing executable exists, provide concrete inspection steps; identify
missing prerequisites or unavailable artifacts honestly.>

## Carried forward

<Unresolved issues, deviations, and follow-up work, with links; or “None”.>

## Records

<Links to existing collected plans, targets, issues, handoffs, and other records,
plus relevant shared references. Omit absent categories.>

## Transition history

| Date | Status | Reason |
| --- | --- | --- |
| <date> | <status> | <reason; include interruptions, closure, and resumption> |
```

Result and Reproduction are required for every closing disposition. Fill real content rather than leaving template placeholders. Do not duplicate the target's full evidence tables or the plan's detailed progress log.
